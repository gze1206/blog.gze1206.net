## 목적

Tailnet 안에서만 접근하는 개인용 웹 워크벤치를 만든다. 빠른 불렛 기록, 비공개 글, 회고, 공개 블로그 글 초안 작성을 한 흐름으로 제공하되, 원본 데이터는 사람이 읽고 Git으로 관리할 수 있는 Markdown 파일로 남긴다.

이 도구의 중심은 생산성 지표나 자동화가 아니라, 짧고 자주 기록하는 Rapid Logging과 의도적인 재검토다. 특히 이월의 번거로움은 할 일의 가치를 다시 판단하는 장치로 보존한다.

## 저장소와 보안 경계

공개 블로그와 개인 기록은 절대 같은 저장소에 두지 않는다.

```text
personal-workbench (private Git)
├── inbox/          빠른 캡처
├── journal/        일일 불렛 노트
├── notes/          장기 메모와 프로젝트 노트
├── drafts/         비공개 글과 발행 후보
├── reviews/        주간·월간 회고
├── templates/      사용자 소유 Markdown 템플릿
└── assets/         비공개 첨부 파일

blog.gze1206.net (public Git)
├── src/content/posts/  공개 Markdoc 글
└── public/             공개 자산
```

개인 웹서비스는 Tailnet 전용으로 노출하고 private 저장소만 읽고 쓴다. 공개 발행은 private에서 public으로 향하는 단방향 수동 작업이다. private 원본, 첨부, Git 이력, 내부 링크가 public 저장소에 섞이는 기능은 만들지 않는다.

## 문서와 템플릿 모델

### 원본 형식

모든 개인 문서는 Markdown과 YAML frontmatter다. 앱 데이터베이스는 원본이 아니며, 도입하더라도 검색 캐시나 임시 인덱스 같은 재생성 가능한 보조 데이터로 한정한다.

### 템플릿

템플릿은 `templates/` 아래의 일반 Markdown 파일이다. 앱은 다음의 최소 frontmatter만 해석한다.

- `title`: 템플릿 목록에서 보일 이름
- `kind`: `capture`, `private-post`, `public-draft`, `weekly-review`, `monthly-review` 등 문서 유형
- `defaultPath`: 새 문서의 기본 저장 위치
- `publicEligible`: 공개 Markdoc 변환 가능 여부

템플릿 본문은 제목, 질문, 체크리스트, 커스텀 Markdoc 블록의 골격을 자유롭게 포함할 수 있다. 템플릿을 생성하면 본문을 새 문서로 복제하고 날짜·식별자 등 새 문서에만 필요한 메타데이터만 채운다.

초기 기본 템플릿은 빠른 메모, 비공개 글, 공개 글 초안, 주간 회고, 월간 회고 다섯 가지다. 앱에서 템플릿을 복제·편집·추가할 수 있으나, 수정 결과는 언제나 파일로 저장한다.

## 불렛 노트 동작

### 빠른 기록

첫 화면은 오늘의 일일 로그다. 키보드만으로 항목을 빠르게 추가할 수 있어야 하며, `•` 메모, `–` 노트, `○` 일정, `□` 할 일의 유형과 완료·취소 상태를 최소 조작으로 정한다. 빠른 캡처는 별도 메모 화면으로 보내지지 않고 오늘의 로그에서 시작한다.

### 의도적 이월

날짜가 바뀌어도 미완료 항목을 자동으로 복제하거나 자동 이월하지 않는다. 이전 일지의 항목은 원래 위치에 남고, 사용자가 검토 화면에서 발견한다.

이월에는 두 가지 설정 가능한 방식이 있다.

1. 간편 이월: 항목 선택 → 이월 → 대상 날짜 확인
2. 의식적 이월: 짧은 확인 문구 입력 → 대상 날짜 확인

두 방식 모두 원본에는 이월 기록을, 새 항목에는 원본 링크를 남긴다. 완료, 취소, 노트화, 비공개 글 초안 승격도 명시적인 사용자 행동이다.

## 회고

주간·월간 회고는 별도 생산성 대시보드가 아니라 템플릿으로 생성하는 문서다.

- 주·월의 시작 또는 종료 시점에 앱을 연 경우에만 회고 작성을 제안한다.
- 자동 문서 생성, 푸시 알림, 반복 독촉은 하지 않는다.
- 사용자는 `작성하기`, `나중에`, `이번에는 건너뛰기`를 선택한다.
- 놓친 기간도 템플릿에서 기간을 지정해 언제든 수동으로 작성할 수 있다.
- 회고에서 기존 불렛과 메모를 링크하고, 이월·완료·취소·노트화·초안 승격처럼 실제 행동으로 정리한다.

## 공개 발행

공개 글 초안은 private 저장소에서 작성한다. `publicEligible: true`인 문서만 발행 대상이 될 수 있다. 발행은 다음 확인을 모두 통과한 뒤에만 public 저장소의 작업 브랜치에 변경을 만든다.

1. 제목, slug, 카테고리, 태그, 발행일을 확인한다.
2. 본문과 자산의 공개 범위를 검사한다.
3. private 링크, private 경로, 비공개 첨부가 남았는지 검사한다.
4. 생성될 Markdoc 파일과 public 저장소 diff를 미리 보여 준다.
5. 사용자가 최종 확인한다.

첫 버전은 public 저장소의 커밋 생성까지만 다룬다. 자동 push와 자동 배포는 하지 않는다.

## 제외 범위

M1에서는 다음을 만들지 않는다.

- 다중 사용자 협업, CRDT, 실시간 동기화
- AI 자동 분류·요약·자동 발행
- 자동 이월
- 모바일 네이티브 앱
- 복잡한 루틴 분석, 시간 추적, 생산성 점수·대시보드
- 템플릿 내부 스크립트와 실행형 자동화

루틴과 타임박싱은 기록 습관과 실제 사용 패턴을 확인한 뒤, 파일 기반 템플릿 또는 작은 확장 기능으로 판단한다.

## 오류 처리와 검증 기준

원본 파일은 실패 시에도 보존한다. frontmatter 오류, 템플릿 파싱 실패, Git 충돌, Markdoc 변환 실패, 공개 범위 검사 실패는 변경을 중단하고 원인·파일 위치·재시도 방법을 보여 준다.

구현 단계에서 다음을 자동 테스트로 고정한다.

- 템플릿을 생성했을 때 본문과 메타데이터가 의도한 경로에 생성된다.
- 미완료 항목이 날짜 경계에서 자동 이월되지 않는다.
- 간편·의식적 이월 모두 원본과 새 항목의 연결 이력을 남긴다.
- 회고 제안은 앱을 연 시점에만 발생하고, 문서를 자동 생성하지 않는다.
- private 전용 링크·경로·자산을 포함한 초안은 공개 변환을 거부한다.
- 공개 변환은 확정 전 public 저장소를 변경하지 않는다.

## 이후 순서

이 문서는 설계 승인본이다. 사용자의 문서 검토 승인을 받은 뒤에만 구현 계획을 작성하고, 그 계획에서 private 저장소 초기화, 파일 모델, 편집 UI, Git 어댑터, 공개 변환기를 독립된 하위 일감으로 분해한다.
