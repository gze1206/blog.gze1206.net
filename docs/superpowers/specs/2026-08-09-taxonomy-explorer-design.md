# 분류 탐색 통합과 관계 그래프 설계

## 목적

카테고리는 포스트의 상위 분류, 태그는 세부 주제라는 기존 콘텐츠 계약을 유지한다. 카테고리·태그의
**목록 인덱스만** 하나의 분류 탐색 화면으로 합쳐, 항목이 적을 때 생기는 두 개의 빈 화면을 없앤다.

## 범위와 URL

- 새 정적 인덱스는 `/topics`이며 제목과 헤더 표기는 `분류`로 한다.
- `/category/[slug]`, `/tags/[slug]`는 각각 결과 목록 URL로 그대로 유지한다. `categoryPath()`와
  `tagPath()`도 바꾸지 않는다.
- 기존 `/category`, `/tags`는 삭제·리다이렉트하지 않는다. 외부 링크와 검색 결과의 호환성을 위해
  기존 목록을 보존하되 `/topics`로 가는 안내 링크를 함께 출력한다.
- 포스트 frontmatter의 `category`, `tags` 스키마와 Keystatic 필드는 변경하지 않는다.

## 정적 탐색 레이어

`/topics`는 자바스크립트 없이도 다음을 실제 HTML 링크로 출력한다.

1. 카테고리 목록: 이름, 글 수, 개별 카테고리 결과 링크.
2. 카테고리별 세부 태그: 해당 카테고리 글에서 파생한 태그 링크와 글 수.
3. 전체 태그: 이름, 전체 글 수, 개별 태그 결과 링크.

같은 글에 같은 태그가 중복 선언되어도 기존 `groupByTag()` 규칙처럼 한 번만 센다. 비어 있는
카테고리나 태그는 표시하지 않는다. 화면의 정보 구조는 `section`·`h2`·목록을 사용하고, 각 링크의
표시 텍스트와 글 수가 접근 가능한 이름에 포함된다.

## 관계 데이터와 그래프

새 순수 모듈 `src/lib/taxonomy-graph.ts`는 노출 대상 글로부터 이분 그래프를 만든다.

- 노드: 모든 카테고리와 태그. `kind`, `slug`, `label`, `count`를 가진다.
- 간선: 한 포스트의 카테고리와 각 태그를 연결한다.
- 가중치: 동일 카테고리-태그 쌍을 다룬 서로 다른 글 수다.
- 순서: label의 한국어 locale 순서로 결정해 빌드 결과가 항상 같다.

`TaxonomyGraph.tsx` React 아일랜드는 `client:visible`로만 로드한다. 외부 시각화 라이브러리나
캔버스/WebGL을 추가하지 않고, 링크가 포함된 SVG를 렌더한다. 카테고리는 왼쪽 열, 태그는 오른쪽
열에 정렬하며 간선의 선 두께는 가중치를 반영한다. 노드는 해당 결과 페이지로 가는 `<a>`라서
마우스·터치·키보드에서 모두 작동한다.

그래프는 보조 시각화이며 정적 목록이 동등한 정보를 제공한다. `prefers-reduced-motion`에서는
그래프 아일랜드를 렌더하지 않고, 좁은 화면은 가로 스크롤 가능한 SVG 컨테이너를 쓴다. SVG에는
짧은 제목·설명을 제공하지만 스크린리더 사용자는 바로 앞의 정적 목록으로 완전하게 탐색한다.

## 구성 요소와 데이터 흐름

```
getVisiblePosts()
 ├─ getCategoryGroups()/getTagGroups() → 정적 목록
 └─ buildTaxonomyGraph(posts) → TaxonomyGraph(client:visible)
```

- `src/pages/topics.astro`: 목록과 그래프 아일랜드를 조립하는 정적 라우트.
- `src/components/TaxonomyExplorer.astro`: 카테고리·카테고리별 태그·전체 태그 목록.
- `src/islands/TaxonomyGraph.tsx`: graph DTO만 받아 SVG를 표시하는 클라이언트 보조 뷰.
- `src/lib/taxonomy-graph.ts`: Astro/React에 의존하지 않는 그래프 파생과 정렬 규칙.

## 검증

- 그래프 파생 단위 테스트: 중복 태그 제거, 간선 가중치, 가나다 결정 순서, draft 미포함 입력의
  데이터 보존.
- 빌드 산출물 검사: `/topics`·기존 인덱스·개별 결과 URL이 생성되고, 정적 링크와 헤더의
  `분류` 링크가 존재한다.
- 키보드/보조 기술: `/topics`의 정적 링크만으로 모든 카테고리·태그 결과에 도달할 수 있다.
- `pnpm test`, `pnpm lint`, `pnpm build`, `pnpm format:check`가 모두 통과해야 한다.

## 비범위

- 포스트 분류 방식 변경, 기존 결과 라우트 제거, 서버 검색, 그래프 필터·드래그·물리 시뮬레이션은
  이 일감에 포함하지 않는다.
