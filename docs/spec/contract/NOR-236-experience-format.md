# NOR-236 — 경력 양식 검사

- 출처: 사용자 요청(2026-11-23). "경력 같은 거 작성할 때 양식에 안 맞아도 발행이 가능한 상태라서 양식 검사를 좀 넣어야 할 것 같아"
- 사례: 워크벤치로 고친 `gameduo` 는 기간을 `2025.05 - 2025.09`(하이픈)로 썼다. 다른 경력은 모두 `YYYY.MM – YYYY.MM`(엔 대시)다.

## 현재

- 계약(`experienceSchema`)은 `period` 를 빈 문자열이 아닌 아무 글자로 받는다.
- `endDate` 는 날짜이기만 하면 받는다. 기간의 끝과 어긋나도, 기간이 "현재" 인데 끝난 날짜가 있어도 막지 않는다.
- 워크벤치가 쓰는 JSON 의 키 순서는 폼이 고친 순서를 따른다. 그래서 새로 넣은 `endDate` 가 맨 뒤로 간다.

## 결정

| 항목      | 결정                                                                                         |
| --------- | -------------------------------------------------------------------------------------------- |
| 기간 형식 | `YYYY.MM – YYYY.MM` 또는 `YYYY.MM – 현재`. 구분자는 앞뒤에 공백 하나를 둔 엔 대시(–)다       |
| 기간 순서 | 시작 달은 끝 달보다 늦을 수 없다                                                             |
| 끝난 날짜 | 기간이 "현재" 면 비어 있어야 하고, 아니면 있어야 하며 그 연·월이 기간의 끝과 같아야 한다     |
| 검사 자리 | 계약 스키마에 둔다. 블로그 빌드와 워크벤치 검토가 같은 규칙으로 막는다                       |
| 입력 보정 | 워크벤치 폼은 `2025.5-2025.9`, `2025.05 ~ 현재` 처럼 모양만 다른 입력을 표준 형식으로 고친다 |
| 키 순서   | 스키마 밖 키(`id` 등)는 원래 순서대로 앞에 두고, 스키마에 있는 키를 스키마 순서로 뒤에 쓴다  |

## 수용 기준

- **AC-1** 계약은 기간이 `YYYY.MM – YYYY.MM` 또는 `YYYY.MM – 현재` 가 아니거나, 월이 01~12 가 아니거나, 시작이 끝보다 늦으면 `period` 오류를 낸다.
- **AC-2** 계약은 기간이 "현재" 인데 끝난 날짜가 있거나, 기간이 끝났는데 끝난 날짜가 없거나, 끝난 날짜의 연·월이 기간의 끝과 다르면 `endDate` 오류를 낸다.
- **AC-3** 워크벤치 폼은 구분자(`-`·`–`·`—`·`~`)와 공백, 한 자리 월만 다른 기간을 표준 형식으로 고쳐 쓰고, 그 밖의 입력은 그대로 둔다.
- **AC-4** 워크벤치가 쓰는 사이트 콘텐츠 JSON 은 스키마에 없는 키를 원래 순서대로 앞에 두고, 스키마에 있는 키를 스키마 순서로 그 뒤에 놓는다.
- **AC-5** 저장소의 경력 데이터는 모두 새 규칙을 통과한다.
