# NOR-237 — 콘텐츠 전반 양식 검사

- 출처: 사용자 요청(2026-11-23). "경력 외에도 전반적으로 양식 체크 필요한지 확인하고 작업한 거 맞지?"
- NOR-236 은 경력만 다뤘다. 이번에는 다른 콘텐츠를 같은 기준으로 점검해 실제로 어긋날 수 있는 곳을 막는다.

## 점검 결과

| 콘텐츠     | 문제                                                                                                            |
| ---------- | --------------------------------------------------------------------------------------------------------------- |
| 포트폴리오 | `period` 가 자유 문자열이다. `boss-toss` 는 `2026.04 ~ 2026.12` 로 다른 항목(엔 대시)과 어긋난다                |
| 글         | `updatedAt` 이 `publishedAt` 보다 이를 수 있다. 다만 정상적인 경우도 있어 막지 않는다(결정 참고)                |
| 글         | 워크벤치는 main 에 없는 시리즈를 가리키는 글도 발행 검토를 통과시킨다. 블로그 빌드가 멈춘다(NOR-235 와 같은 꼴) |
| 글         | 카테고리·태그가 자유 문자열이라 오타 하나로 새 카테고리 페이지가 생긴다                                         |
| 책         | `finishedAt` 이 `startedAt` 보다 이를 수 있다                                                                   |
| 책         | `relatedPost` 를 검사하지 않아, 없는 글이나 draft 를 가리키면 공개 페이지에 깨진 링크가 생긴다                  |
| 프로필     | 주소 scheme 검사가 있다. 추가할 것이 없다                                                                       |
| 시리즈     | slug 와 파일 이름 일치, 삭제 시 참조 검사(NOR-235)가 있다. 추가할 것이 없다                                     |

## 결정

| 항목             | 결정                                                                                                                                                                                                                    |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 포트폴리오 기간  | 있으면 경력과 같은 `YYYY.MM – YYYY.MM` 또는 `YYYY.MM – 현재` 형식이다. 예정된 작업이 있으므로 미래의 끝 달은 받는다                                                                                                     |
| 날짜 순서        | 책만 계약에서 막는다(같은 날은 받는다). 글의 `updatedAt` 은 워크벤치가 문서를 고친 시각으로 채우므로, 예약 발행이나 시간대가 다른 `publishedAt` 과 견주면 정상적인 글을 막는다. 그래서 글에는 넣지 않는다(AC-2 를 뺐다) |
| 참조 무결성      | 워크벤치 검토가 main 사본을 읽어 거절한다. 시리즈는 존재, 관련 글은 공개(draft 아님) 글이어야 한다                                                                                                                      |
| 새 카테고리·태그 | 막지 않고 검토 화면에 경고한다. 새 분류를 만드는 것은 정상적인 일이다                                                                                                                                                   |
| 대소문자 태그    | 기존 태그와 대소문자만 다른 태그는 경고한다                                                                                                                                                                             |
| 비교 대상        | main 의 공개 글이 하나도 없으면 비교하지 않는다. 첫 글은 모든 분류가 새것이라 경고가 뜻이 없다                                                                                                                          |

## 수용 기준

- **AC-1** 계약은 포트폴리오 `period` 가 있을 때 경력과 같은 형식이 아니거나 시작이 끝보다 늦으면 `period` 오류를 낸다. 워크벤치 폼은 포트폴리오 기간도 경력처럼 표준 형식으로 고친다.
- **AC-3** 계약은 책의 `finishedAt` 이 `startedAt` 보다 이르면 `finishedAt` 오류를, `relatedPost` 가 slug 형식이 아니면 `relatedPost` 오류를 낸다.
- **AC-4** 워크벤치 글 발행 검토는 main 에 없는 시리즈를 가리키는 글을 거절한다.
- **AC-5** 워크벤치 글 발행 검토는 main 의 공개 글에 없던 카테고리와 태그, 기존 태그와 대소문자만 다른 태그를 경고로 알린다.
- **AC-6** 워크벤치 책 내보내기 검토는 `relatedPost` 가 main 의 공개 글이 아니면 거절한다.
- **AC-7** 저장소의 포트폴리오·글·책 데이터는 모두 새 규칙을 통과한다.
