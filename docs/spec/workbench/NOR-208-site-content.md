# NOR-208 — 워크벤치에서 사이트 콘텐츠(프로필·경력·포트폴리오·시리즈) 편집과 발행

- 출처: 사용자 보고(2026-11-15). 홈·소개·경력·포트폴리오·시리즈 콘텐츠를 추가·수정·삭제할 방법이 없다.
- 이어받는 것: 확정한 커밋을 공개 블로그로 보내는 마지막 단계는 NOR-210(릴레이가 PR 을 만들고 CI 통과 시 자동 병합)으로 정리됐다. 여기서는 그 경로에 사이트 콘텐츠를 싣는다.

## 결정

| 항목   | 결정                                                                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 원본   | 사이트 콘텐츠는 공개 저장소의 JSON 이 원본이다. 워크벤치는 사본을 두지 않고, 검토할 때마다 새로 받은 main 을 읽고 고친다                   |
| 스키마 | 프로필·경력·포트폴리오 스키마를 `@gze1206/content-contract` 로 옮긴다. 블로그와 워크벤치가 같은 객체로 검사한다(시리즈는 이미 계약에 있다) |
| 형식   | 저장소 Prettier(json, printWidth 100)와 같은 모양으로 쓴다. 화면에 없는 필드는 그대로 남긴다                                               |
| 경로   | 릴레이 허용 목록에 `profile.json` 과 `experience`·`portfolio`·`series` 의 `<slug>.json` 을 더한다. 이미지 올리기는 이번 범위가 아니다      |
| 삭제   | 경력·포트폴리오·시리즈 항목은 지울 수 있다. 프로필은 하나뿐이라 지울 수 없다                                                               |

## 수용 기준

### 계약과 경로

- **AC-1** 계약 패키지는 `profileSchema`·`experienceSchema`·`portfolioSchema` 와 사이트 콘텐츠 자리(`SITE_COLLECTIONS`)를 내보내고, 블로그 스키마는 그 객체를 그대로 쓴다.
- **AC-2** 릴레이 허용 목록은 `apps/blog/src/content/profile.json` 과 `experience`·`portfolio`·`series` 아래 slug 이름의 `.json` 을 받고, 그 밖의 경로(`content.config.ts`, 하위 디렉터리, 대문자·점으로 시작하는 이름)는 받지 않는다.

### 서버

- **AC-3** `GET /api/site` 는 새로 받은 main 의 사이트 콘텐츠를 `{ collection, id, data }` 목록으로 돌려준다. 읽지 못한 파일은 목록에서 빼지 않고 문제로 함께 돌려준다.
- **AC-4** `POST /api/site/review` 는 `{ collection, id, data }`(쓰기) 또는 `{ collection, id, delete: true }`(삭제)를 받아 계약 스키마로 검사하고, 바뀌는 줄 diff 와 `reviewId` 를 돌려준다. 바뀐 것이 없으면 `noop` 이고, 검사에 실패하면 필드별 오류를 400 으로 돌려준다. id 는 slug 이고 프로필의 id 는 `profile` 뿐이다.
- **AC-5** `POST /api/site/confirm` 은 검토한 그대로를 커밋으로 만들어 outbox 에 남긴다. 브랜치는 `content/site-<collection>-<ASCII 키>` 이고, 검토 뒤 main 이나 입력이 바뀌었으면 발행하지 않는다.

### 화면

- **AC-6** 옆 막대에 "사이트 콘텐츠" 가 있고, 프로필·경력·포트폴리오·시리즈 항목을 고르거나 새로 만들 수 있다.
- **AC-7** 항목은 폼으로 고친다. 문자열·여러 줄·목록(한 줄에 하나)·참거짓·링크 같은 행 목록을 칸으로 보여 주고, 검토하면 diff 를 보인 뒤 "발행" 으로 확정한다.

### 검수 반영 (PR #54)

- **AC-8** 링크는 `http(s)` 만 받는다(프로필 링크는 `mailto:` 도 받는다). `javascript:`·`data:` 와 제어 문자가 섞인 주소는 받지 않는다. 포트폴리오 이미지·썸네일 경로는 `/` 로 시작하는 사이트 안 경로만 받고(`//`·`..` 금지), 시리즈의 `slug` 는 파일 이름과 같아야 한다.
- **AC-9** 목록은 항목마다 원본 해시를 함께 돌려주고, 검토·확정은 편집을 시작한 때의 해시(`baseHash`, 새 항목은 `null`)가 main 과 다르면 거절한다. main 에 없던 새 최상위 키(스키마 밖)는 받지 않고, 행 목록의 화면에 없는 필드는 남긴다. 요청 본문은 256KB 까지, 같은 검토를 동시에 두 번 확정할 수 없다. JSON 형식은 이모지를 두 칸으로 세고, 마지막 요소에는 쉼표 칸을 세지 않는다.
