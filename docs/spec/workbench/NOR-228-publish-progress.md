# NOR-228 — 발행 상태 배지 자리와 발행 진행 토스트

- 출처: 사용자 요청(2026-11-15). 발행 상태를 불러오는 1~2초 동안 배지 자리가 비어 있다. 발행을 확정한 뒤에는 PR·검사·병합이 어디까지 왔는지 알 수 없다.

## 흐름과 관찰 지점

1. 확정: 컨테이너가 outbox 에 매니페스트(`<이름>.json`)를 쓴다. 응답의 `outboxRef` 가 그 이름이다.
2. 릴레이: 호스트 릴레이가 1분마다 매니페스트를 검사해 `content/*` 브랜치로 push 하거나 거절하고, ledger 에 `<이름> ok <브랜치>` · `<이름> rejected|stale <사유>` 를 남긴다.
3. PR·검사: 브랜치에 PR 이 열리고 CI 가 돈다. 통과하면 자동 병합된다.

컨테이너는 ledger 를 읽을 수 없다(호스트 0700). 릴레이가 같은 내용의 **공개 사본**을 `RELAY_STATE/public/ledger`(디렉터리 0755, 파일 0644)에 쓰고, 컨테이너는 그 디렉터리를 읽기 전용으로 마운트한다. 사본에는 매니페스트 이름·브랜치 이름·고정 사유 코드만 있다. PR 과 검사 상태는 공개 저장소이므로 GitHub REST API 를 자격 없이 조회한다.

## 결정

| 항목      | 결정                                                                                                                                                              |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 단계      | `queued`(릴레이 대기) → `relayed`(PR 여는 중) → `checking`(검사 중) → `merged`. 끝 상태: `merged`·`failed`(검사 실패)·`closed`(병합 없이 닫힘)·`rejected`·`stale` |
| ledger    | 공개 사본을 읽기 전용 마운트로 읽는다. 없으면 모든 발행이 `queued` 로 남는다                                                                                      |
| GitHub    | `PUBLIC_BLOG_REMOTE` 의 owner/repo 로 PR(`head=<owner>:<branch>`)과 check-runs 를 조회한다. 브랜치마다 30초 캐시, 실패·한도 초과는 `relayed` 로 둔다              |
| 조회 API  | `GET /api/publish/progress?ref=<이름>.json`(최대 10개). 이름은 릴레이와 같은 규칙만 받는다                                                                        |
| 토스트    | 앱 최상단. 진행 중인 발행을 localStorage 에 기억해 화면 이동·새로고침 뒤에도 이어서 10초마다 묻는다. 병합되면 발행 상태를 다시 읽는다                             |
| 배지 자리 | 상태를 불러오는 동안 공개 글마다 "확인 중" 배지를 둔다                                                                                                            |

## 수용 기준

- **AC-1** `parseLedger` 는 ledger 줄을 이름별 결과(`ok` 브랜치, `rejected`·`stale` 사유)로 읽고, 모양이 다른 줄은 무시한다. 같은 이름이 여러 번 나오면 마지막 줄을 쓴다.
- **AC-2** `publishProgress` 는 ledger 결과와 PR 조회 결과로 단계를 정한다(위 표).
- **AC-3** GitHub 조회는 PR 상태와 검사 결과(`pending`·`success`·`failure`)를 돌려주고, 같은 브랜치는 30초 안에 다시 묻지 않으며, 실패하면 `null` 이다.
- **AC-4** `GET /api/publish/progress` 는 이름 규칙에 맞지 않거나 10개를 넘는 요청을 400 으로 거절하고, 이름마다 단계를 돌려준다.
- **AC-5** 토스트 저장소는 발행을 더하고, 단계를 갱신하고, 끝난 발행을 구분하고, localStorage 로 다시 읽는다. 깨진 값은 버린다.
- **AC-6** 문서 목록은 상태를 불러오는 동안 공개 글에 "확인 중" 배지를 둔다.
- **AC-7** 릴레이는 ledger 를 쓸 때마다 공개 사본(0644)을 원자적으로 갱신한다.
