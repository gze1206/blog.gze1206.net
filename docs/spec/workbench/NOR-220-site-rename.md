# NOR-220 — 사이트 콘텐츠 이름 바꾸기와 발행 대기 표시

- 출처: 사용자 보고(2026-11-15). 포트폴리오 이름을 바꾸면 제대로 수정되지 않는다.
- 원인: (1) 기존 항목은 파일 이름(id)을 바꿀 수 없어, `portfolio/blog-v4.json` 이 다른 프로젝트(Boss Toss)를 담게 된다. (2) 목록은 main 을 읽으므로, 발행한 PR 이 병합되기 전에는 옛 내용이 보인다.

## 결정

| 항목        | 결정                                                                                                                          |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 이름 바꾸기 | 경력·포트폴리오만 바꾼다. 시리즈는 글이 파일 이름으로 참조하므로 바꾸지 않는다. 프로필은 하나뿐이다                           |
| 커밋        | 한 커밋 안에서 새 파일을 쓰고 옛 파일을 지운다. JSON 의 `id` 가 옛 이름이면 새 이름으로 바꾼다                                |
| 대기 표시   | 발행하면 목록에 새 내용과 "반영 대기" 를 보이고, 병합 전에는 그 항목을 다시 고치지 않게 한다. "main 다시 읽기" 로 새로 읽는다 |

## 수용 기준

- **AC-1** 검토·확정은 `renameFrom`(옛 id)을 받는다. 경력·포트폴리오에서만, 옛 id 와 다른 slug 로만 받는다. 기준 해시는 옛 파일과 견주고, 새 이름의 파일이 이미 있으면 거절한다.
- **AC-2** 이름을 바꾼 발행은 새 파일을 쓰고 옛 파일을 지운 커밋 하나를 만들고, diff 에 두 파일을 모두 보인다. JSON 의 `id` 가 옛 이름이면 새 이름으로 쓴다.
- **AC-3** 경력·포트폴리오 폼은 기존 항목에도 "파일 이름" 을 보이고, 바꾸면 이름 바꾸기로 검토한다. 시리즈 폼은 기존 항목의 파일 이름을 바꿀 수 없다.
- **AC-4** 발행에 성공하면 목록이 그 항목을 새 내용·새 이름과 "반영 대기" 로 보이고, 그 항목은 반영되기 전에는 다시 검토할 수 없다. "main 다시 읽기" 는 목록을 새로 읽는다.
