# NOR-219 — 사이트 콘텐츠 폼 입력 보존과 포트폴리오 이미지 업로드

- 출처: 사용자 보고(2026-11-15). 여러 줄 칸에서 줄바꿈·스페이스가 먹지 않는 경우가 있고, 포트폴리오 이미지는 업로드가 아니라 경로를 손으로 적어야 한다.
- 원인: 폼이 키를 누를 때마다 칸의 글을 데이터(목록)로 바꿨다가 다시 글로 그리며 빈 줄·앞뒤 공백을 버렸다. 행 목록 칸도 공백을 잘랐다.

## 결정

| 항목 | 결정                                                                                                                |
| ---- | ------------------------------------------------------------------------------------------------------------------- |
| 입력 | 칸마다 입력한 글을 그대로 들고 있고, 데이터로 바꾸는 일은 그 글에서 한다. 화면은 데이터에서 다시 그리지 않는다      |
| 저장 | 올린 이미지는 작업 공간 `assets/site/portfolio/` 에 내용 해시가 붙은 이름으로 둔다. 같은 이미지는 같은 이름이다     |
| 형식 | JPEG·PNG·WebP 만, 5MB 까지. 형식은 내용으로 판별하고 너비·높이를 함께 돌려준다                                      |
| 발행 | 포트폴리오를 발행하면 JSON 이 참조하는 `/img/portfolio/<이름>` 중 작업 공간에 있고 블로그와 다른 것을 함께 내보낸다 |

## 수용 기준

- **AC-1** 사이트 콘텐츠 폼의 여러 줄 칸·한 줄 칸·행 목록 칸은 입력한 줄바꿈·빈 줄·공백을 그대로 보인다. 데이터는 그 글에서 만든다(목록은 빈 줄을 빼고 다듬는다).
- **AC-2** `POST /api/site/images` 는 이미지 바이트를 받아 `{ src: '/img/portfolio/<이름>', width, height }` 를 돌려주고, `GET /api/site/images/<이름>` 은 그 파일을 내준다. 이미지가 아니거나 5MB 를 넘거나 이름 모양이 다르면 거절한다.
- **AC-3** 포트폴리오 검토·발행은 `media[].src`·`thumbnail` 이 가리키는 `/img/portfolio/<이름>` 을 작업 공간에서 찾아, 블로그에 없거나 내용이 다르면 커밋에 더하고 diff 에 알린다. 작업 공간에도 블로그 `public/` 에도 없는 이미지 경로는 400 으로 거절한다. 메타데이터(EXIF 등)가 있으면 경고한다.
- **AC-4** 릴레이 허용 목록은 `apps/blog/public/img/portfolio/<slug 이름>.(png|jpg|jpeg|webp)` 를 받는다.
- **AC-5** 포트폴리오 폼은 이미지마다 미리보기와 "이미지 올리기" 를 두고, 올리면 경로·너비·높이를 채운다. 썸네일도 올릴 수 있다.

### 이미지 경로 입력 전반 (사용자 요청 2026-11-15)

- **AC-6** 공개 초안 편집기의 도구 막대 "이미지" 는 이미지를 올려 `assets/public/<문서>/<이름>-<해시>.<확장자>` 에 두고, 커서 자리에 `![설명](<파일 이름>)` 을 넣는다. 올린 이미지는 발행 자산 목록에 나타나고 선택된다. `POST /api/publish/assets/:id` 는 공개 초안에만 열리고, 이미지가 아니거나 5MB 를 넘으면 거절한다.

### 검수 반영 (PR #62)

- **AC-7** 발행할 때 고른 본문 자산은 모두 본문이 참조해야 한다. 참조하지 않는 자산을 고르면 거절한다. 올린 이미지는 형식의 끝(PNG `IEND`·JPEG `EOI`·WebP RIFF 길이)까지 갖춘 파일만 받고, 이름의 해시는 16자다. 같은 이름에 다른 내용이 오면 거절한다. 업로드가 끝났을 때 항목·문서·행이 바뀌었으면 결과를 다른 곳에 반영하지 않는다.
