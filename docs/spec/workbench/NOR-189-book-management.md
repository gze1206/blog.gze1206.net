# NOR-189 — 워크벤치 읽은 책 관리 명세

## 목적

읽은 책을 워크벤치에서 등록하고, 서지정보와 표지를 **등록하는 순간 한 번** 받아 작업 공간에
보관한다. 목록은 블로그로 나갈 수 있고(NOR-188), 상세 메모는 기본적으로 나가지 않는다.

## 설계 결정

- **수기 입력이 기본, ISBN 조회는 보조다.** 제목과 저자만 있으면 책 항목이 성립한다. 조회가
  비어도 등록은 막히지 않는다.
- **조회는 등록 시점에 한 번.** 화면을 그릴 때마다 남의 서버를 부르지 않는다. 받은 표지는
  `assets/books/<isbn13 또는 slug>.<ext>` 로 내려받아 두므로, 나중에 제공처가 사라져도
  목록은 그대로 남는다.
- **제공처는 포트 뒤에 둔다.** `BookMetadataProvider` 는 `src/core/books/metadata.ts` 의
  순수 포트이고, HTTP 구현은 `src/server/adapters/bookMetadata.ts` 하나뿐이다. 네이버 책이나
  국립중앙도서관(키가 필요한 대신 국내서를 안다)으로 바꿀 때 이 파일 하나만 갈아끼운다.
- **읽은 목록은 공개가 기본(`visible: true`), 본문 메모는 문서 본문에 둔다.** 블로그로 나가는
  것은 목록 필드이지 본문이 아니다.
- **진도는 페이지만 남긴다.** 앱마다 %(책 내 지점) 지원이 달라 비교할 수 없다.

## 키 없는 제공처의 실제 커버리지 (2026-08-19 실측)

Open Library → Google Books 순으로 본다. 둘 다 키가 필요 없지만 국내서에 약하다.

| ISBN                                 | 결과                                 |
| ------------------------------------ | ------------------------------------ |
| 9780140449136 (Crime and Punishment) | 제목·저자·출판사·표지까지 채움       |
| 9788934972464 (사피엔스)             | 제목이 로마자 `Sap'iensŭ`, 표지 없음 |
| 9791162243664 (국내 실용서)          | 못 찾음                              |

추가로 Google Books 는 이 회선에서 **429(요청 과다)** 를 돌려주고, Open Library 도 연속 호출에서
간헐적으로 빈 응답을 준다. 즉 **조회 실패는 예외가 아니라 정상 경로**다. 그래서 화면은 조회 결과를
기다리지 않고도 저장할 수 있어야 하고, 실패는 "직접 적어 넣으세요" 안내로만 끝난다.

## 독서 기록 네 가지는 별개다

한 덩어리의 "메모"로 두면 나중에 구분할 수 없다. 가르는 축은 두 개다 — **누구의 말인가**,
그리고 **어디에 매이는가**. 여기에 _언제 쓰는가_ 가 하나를 더 갈라놓는다: 읽는 도중에 던져
두는 것과 다 읽고 앉아서 쓰는 것은 같은 것이 아니다.

|                               | 누구의 말 | 매이는 곳      | 언제    | 공개                         |
| ----------------------------- | --------- | -------------- | ------- | ---------------------------- |
| 구절 (`excerpts[].text`)      | 저자      | 그 페이지      | 읽다가  | 남의 저작물. 내보내지 않는다 |
| 구절 메모 (`excerpts[].memo`) | 나        | 그 구절        | 읽다가  | 비공개                       |
| 독서 메모 (`memos[]`)         | 나        | 책 (쪽은 선택) | 읽다가  | 비공개                       |
| 독서 노트 (문서 본문)         | 나        | 책 전체        | 다 읽고 | 비공개                       |

구절 메모와 독서 메모를 굳이 나누는 이유: 옮겨 적을 문장이 없어도 떠오르는 생각이 있다.
그것을 억지로 어떤 구절 밑에 달면, 나중에 그 구절을 지울 때 상관없는 생각까지 딸려 나간다.

블로그로 나가는 감상은 `oneLiner` 한 줄뿐이고 그것은 내가 쓴 말이다. 구절을 공개하려면
인용의 요건(출처·분량)을 사람이 그때 판단해야 하므로, 자동으로 흘러가는 길을 아예 두지 않는다.

구절은 frontmatter 의 목록이고 메모는 본문이다. 여러 줄 구절은 YAML 블록 스칼라(`|-`)로
원문 그대로 오간다. 페이지는 **없을 수 있다** — 페이지를 알려 주지 않는 앱이 있다.

구절과 독서 메모는 담기는 것이 다를 뿐 다루는 법이 같아 한 길로 묶었다
(`POST|PUT|DELETE /api/books/:id/{excerpts|memos}[/:index]`). 한 줄을 남길 때 문서 전체를 다시
쓰게 하지 않는다 — 읽다가 남기는 일은 자주 있고, 그때마다 본문을 통째로 보내면 편집기에서
독서 노트를 쓰던 것과 서로 덮어쓴다.

## 마크다운 대신 폼

독서 기록을 남기자고 YAML 을 손으로 맞추게 하지 않는다. 책 문서는 폼으로 연다 — 상태·날짜·
별점은 고르는 것이고, 독서 노트는 그냥 글칸이며, 구절과 메모는 각자의 목록이다.

그래도 **파일이 원본이라는 전제는 그대로다**. `원본 고치기` 로 언제든 마크다운을 직접 연다.
폼이 모르는 필드(사람이 손으로 넣어 둔 것)는 저장해도 사라지지 않고, 제목을 고쳐도 파일
이름은 그대로다 — 파일이 옮겨 다니면 표지와의 짝이 끊긴다.

## 문서 계약

```yaml
---
title: 사피엔스
kind: book
authors: ['유발 하라리']
publishedYear: 2016
isbn13: '9788934972464' # 있으면 파일 이름이 된다
cover: assets/books/9788934972464.jpg
coverSource: Open Library
status: reading | finished | abandoned | want
excerpts: # 옮겨 적은 구절. 없으면 아예 없는 키다
  - page: 42 # 모르면 없다
    text: |-
      저자의 문장 그대로
    memo: 그 문장에 대한 내 생각
    addedAt: 2026-08-20
memos: # 옮길 문장 없이 남긴 생각
  - page: 200 # 모르면 없다
    text: 3부부터 늘어진다
    addedAt: 2026-08-20
format: ebook | paper | audio
source: library | purchase | subscription | borrowed
visible: true # 목록 공개 여부. 본문 메모는 별개다
---
비공개 메모 본문
```

`authors` 는 하나 이상, `status` 는 필수다(`validateKindFields`). ISBN 이 없으면 제목을 슬러그로
쓰되(`bookSlug`) 한글은 그대로 살린다 — 로마자로 옮기면 목록에서 사람이 못 알아본다.

## 하지 않은 것

- **북마크(위치만 표시)**: 읽던 자리를 표시하는 일은 읽는 앱이 이미 한다. 여기 옮겨 적을
  이유가 없다 — 여기 남길 것은 다시 볼 것들이다.
- **구절 고치기·지우기**: 지금은 더하기만 있다. 잘못 적은 것은 문서를 직접 고친다. 손으로
  고칠 수 있는 파일이 원본이라는 것이 이 도구의 전제이므로 급하지 않다.
- **구절 공개**: 위의 이유로 길 자체를 두지 않았다.
- **표지 없는 책의 대체 표지**: 블로그 책장(NOR-188)에서 정한다.
