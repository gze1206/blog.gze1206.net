# NOR-233 — 워크벤치를 휴대폰 화면에 맞추기

- 출처: 사용자 요청(2026-11-22). "워크벤치 모바일 최적화가 전혀 안 된 것 같네"

## 현재

- `body` 에 `min-width: 52rem` 이 있어 390px 화면에서도 페이지가 833px 폭으로 그려진다.
- 사이드바(`w-80`)가 늘 본문 옆에 붙어 있어 본문이 화면 밖으로 밀린다.
- 편집기 머리글, 책 편집기의 3열 칸, 사이트 콘텐츠의 목록(`w-64`), 발행 검토의 표가 모두 넓은 화면을 가정한다.
- 입력 칸 글자가 14px 라 iOS Safari 가 칸을 누를 때마다 화면을 확대한다.

## 결정

| 항목        | 결정                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------ |
| 경계        | 768px(`md`) 미만을 좁은 화면으로 본다. 그 이상은 지금 모양을 그대로 둔다                   |
| 사이드바    | 좁은 화면에서는 왼쪽 서랍으로 접는다. 위쪽 막대의 메뉴 버튼으로 열고, 무엇을 고르면 닫는다 |
| 테마 버튼   | 서랍 머리에 하나만 둔다. 두 벌을 두면 상태가 어긋난다                                      |
| 편집기      | 나란히 보기는 좁은 화면에서 위아래로 쌓는다. 머리글 버튼은 줄을 바꿔 감싼다                |
| 각 화면     | 좌우 여백을 줄이고, 고정 열 칸은 좁은 화면에서 한 열로 쌓는다                              |
| 입력 글자   | 좁은 화면에서 입력 칸과 편집기 본문은 16px 이상으로 그린다(iOS 확대 방지)                  |
| 발행 토스트 | 좁은 화면에서 좌우 여백 안으로 넓힌다                                                      |

## 수용 기준

- **AC-1** 390px 화면에서 오늘의 로그, 문서 편집기(편집·나란히), 책 편집기, 사이트 콘텐츠, 발행 검토가 가로로 넘치지 않는다.
- **AC-2** 768px 미만에서는 사이드바가 숨고 메뉴 버튼으로 연다. 문서를 고르거나 메뉴 항목을 누르면 닫히고, Esc 와 바깥 영역 누르기로도 닫힌다. 768px 이상에서는 메뉴 버튼이 없고 사이드바가 늘 보인다.
- **AC-3** 좁은 화면에서 글자 입력 칸의 글자 크기는 16px 이상이다.
