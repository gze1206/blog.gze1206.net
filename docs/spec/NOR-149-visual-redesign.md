# NOR-149~152 — 시각 언어 재구축 (팔레트 · 읽기 · 홈 · 탐색)

> 대상 일감: NOR-149(팔레트·마크), NOR-150(글 상세), NOR-151(홈·경력·포트폴리오), NOR-152(탐색 지도)
> 상태: done · 근거: 2026-08-13 목업 세션에서 확정한 방향

## 배경

기존 화면은 파란 계열 기본 팔레트와 좁은 단일 폭 위에 있었고, 분류 맵은 카테고리와 태그를 두
열로 세운 이분 그래프였다. 읽기에 필요한 위계(제목 / 본문 / 코드)와 탐색에 필요한 정보(무엇이
무엇과 얼마나 자주 만나는가)가 화면에 드러나지 않았다.

## 확정한 것

### 색

팔레트 **02C Mineral / Warm Paper**. 라이트 `#FCF9F4` 종이 · `#292623` 잉크,
다크 `#211F1D` · `#EFECE7`, 강조 `#3D7364` / `#9FD0BB`.

- 초록은 **신호에만** 쓴다. 표면까지 물들이면 독서 공간이 테마성 UI 처럼 보인다.
- 색 값은 `--theme-*` 토큰 하나에서만 정의한다. 토큰이 라이트·다크를 모두 알기 때문에
  `.dark` 로 같은 값을 다시 쓰는 규칙은 두지 않는다.
- 콜아웃 다섯 색은 브랜드 초록과 겹치지 않게 고르고, 각자의 배경 위에서 AA(4.5:1)를 넘긴다.

### 글자

- 본문·UI 는 Pretendard, **제목만** Noto Serif KR 600.
- 한글 세리프는 `unicode-range` 로 쪼갠 정의를 쓴다. 통짜 한글 서브셋은 957 KB 라 제목 한 줄
  때문에 1 MB 를 받게 된다.
- h3 이하는 산세리프 굵기로 위계를 만든다. 작은 크기의 세리프는 화면에서 오히려 읽기 어렵다.

### 마크

**B1 Swept Tines** — 닉네임 NORU 에서 온 정면 노루 얼굴. 뿔은 얇고 얼굴의 중심축은 굵다.
파비콘처럼 작은 크기에서는 굵은 컷을 쓴다. `gze1206` 은 주소로만 쓰고 마크의 재료로 쓰지 않는다.

### 폭

| 요소                                    | 폭     |
| --------------------------------------- | ------ |
| 헤더·푸터 격자                          | 1200px |
| 글의 모든 것 (제목·목차·본문·코드·댓글) | 900px  |

**한 열이다.** 처음에는 셋으로 나눴다 — 제목·목차 980, 본문 900, 코드는 본문보다 좌우로 더
나가게. 각 요소의 역할을 폭으로 말하려던 것이었다. 실제로 띄워 보니 위계가 아니라 **어긋난
줄**로 보였다: 한 화면 안에 왼쪽 끝이 세 군데였고, 그중 무엇도 다른 것의 기준으로 읽히지
않았다. 코드가 다른 종류의 내용이라는 것은 배경색과 테두리가 이미 말하고 있으므로 폭까지
동원할 필요가 없다.

덤으로 버그도 하나 사라졌다. 코드를 넓히는 값이 `4vw` 였는데 글의 좌우 여백은 `1rem` 고정이라,
화면이 400~980px 인 구간에서 코드가 화면 밖으로 삐져나가 페이지 전체에 가로 스크롤이 생겼다
(820px 화면에서 17px). 계약 검사 `verifyReadingColumn` 이 이 둘을 함께 붙잡는다.

### 목차

`<details>` 로 여닫는다. 스크립트는 플로팅 목차의 **노출 시점**만 정한다.
frontmatter `toc: auto | inline | floating | false` (기본 `auto`).

### 홈

입구다. 소개 → 최근 기록 → 두 개의 문(`/career`, `/portfolio`). 홈에서 프로젝트를 늘어놓지
않는다. 깊이는 각자의 공간에서 본다.

### 탐색

한 페이지에 카테고리 카드 · 관계 지도 · 태그 색인.

- 노드 크기 = 그 분류의 글 수, 간선 굵기·농도 = 그 조합의 글 수
- 태그–태그 보조선은 선택했을 때, 선택한 노드에 닿는 것만
- 기본은 전체 보기. 선택하면 1·2차 관계만 남고 언제든 해제할 수 있다
- 좌표는 빌드타임에 고정한다. 방문할 때마다 지도가 달라지면 "저번에 저기 있던 태그"라는
  기억이 무의미해지고 공유한 링크도 재현되지 않는다
- 지도는 보조 수단이다. 앞뒤의 정적 목록으로 같은 곳에 갈 수 있어야 한다
