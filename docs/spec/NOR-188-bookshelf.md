# NOR-188 — 읽은 책 책장

## 목적

읽은 책 목록을 표지가 서 있는 책장으로 보인다. 워크벤치가 등록 시점에 표지를 받아 두므로
(NOR-189) 이제 목록에 그림이 생긴다.

## 설계 결정

- **표지 없음이 평상시다.** 키 없이 쓸 수 있는 서지정보 제공처는 국내서 표지를 자주 모른다
  (NOR-189 실측: 세 권 중 한 권만 표지를 얻었다). 그래서 표지 없는 책도 자리를 지키도록
  제목에서 색을 정해 세운다 — 빈 회색 상자를 두면 책장이 고장 난 것처럼 보인다.
- **색은 제목의 함수다.** `spineTone()` 은 제목을 해시해 다섯 색 중 하나를 고른다. 무작위로
  두면 다시 빌드할 때마다 색이 바뀌어 같은 책을 같은 책으로 알아볼 수 없다.
- **표지는 2:3 로 잘라 세운다.** 실제 표지 비율은 제각각이라 그대로 두면 선반이 울퉁불퉁해진다.
  `object-fit: cover` 로 잘라도 표지는 알아볼 수 있고, 제목은 바로 아래에 글자로 있다.
- **선반은 칸마다 그린다.** 칸 간격만큼 양옆으로 넘긴 선을 각 칸 아래에 두면, 몇 줄로 접히든
  줄마다 하나의 판처럼 이어진다. 줄 수를 미리 알 필요가 없다.
- **"읽는 중" 은 표지 위 갈피로 얹는다.** 지금 손에 든 책이 책장에서 먼저 보여야 한다. 나머지
  상태(완독·중단·읽고 싶은)는 표지 아래 글자로만 적는다 — 다 지나간 일이다.
- **책마다 상세 페이지를 만들지 않는다**(NOR-153 결정 유지). 밑줄과 메모는 워크벤치에 남는다.

## 위치

푸터 링크만으로는 아무도 지나가지 않는다. 상단 메뉴는 네 개로 유지해야 하므로(NOR-149),
소개 페이지 옆단에 **요즘 읽는 것** 세 권을 두고 책장으로 보낸다. 무엇을 읽는 사람인지는
소개의 일부다. 푸터 링크는 그대로 둔다.

## 남은 간극

워크벤치가 쓰는 `cover` 는 파일 경로 문자열(`assets/books/<isbn>.jpg`)이고, 블로그 스키마의
`cover` 는 `{ src, width, height, source }` 객체다. 워크벤치에서 블로그로 책을 내보내는 경로를
만들 때 이 변환을 어디서 할지 정해야 한다 — 아직 그 경로가 없어 지금은 문제가 되지 않는다.
