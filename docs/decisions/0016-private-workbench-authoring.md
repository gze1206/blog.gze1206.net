# 0016. private Tailnet 워크벤치를 유일한 작성 진입점으로 사용

## 맥락 (Context)

공개 블로그는 독자가 읽는 정적 콘텐츠를 안정적으로 제공해야 한다. 이전의 공개 CMS 런타임은 작성 편의를
위해 공개 사이트에 인증, 비밀값, 동적 API와 운영 절차를 함께 두었다. 작성·비공개 보관·공개용 변환을
공개 전달 경로와 분리할 필요가 생겼다.

## 검토한 대안 (Options)

- **A안: 공개 블로그에 CMS 런타임을 유지** — 브라우저에서 바로 작성할 수 있지만, 공개 배포에 동적
  경로와 인증 운영을 계속 결합한다.
- **B안: private Tailnet 워크벤치만 작성 진입점으로 사용** — 작성 환경을 비공개 네트워크로 제한하고,
  공개 블로그는 정적 산출물만 제공한다.

## 결정 (Decision)

**B안을 선택한다.** private Tailnet 워크벤치를 작성, 비공개 보관, 공개용 콘텐츠 변환의 유일한 진입점으로
둔다. 공개 블로그는 Content Collections와 Markdoc로 생성한 정적 산출물만 배포한다.

## 근거 (Rationale)

작성 권한과 비밀값, 미공개 초안을 공개 전달 경로에서 분리하면 공개 블로그의 공격 표면과 운영 복잡도가
줄어든다. 정적 산출물은 기존의 크롤러 우선·점진적 향상 원칙도 그대로 지킨다. 이 결정은 과거 CMS 도입의
이력 자체를 지우지 않으며, ADR 0012와 0015의 현재형 결정을 대체한다.

## 영향 (Consequences)

- 긍정: 공개 배포에는 동적 작성 경로와 CMS 인증 비밀값이 없다.
- 긍정: 작성·비공개 보관·변환 경계가 private Tailnet 워크벤치로 명확해진다.
- 비용: 워크벤치 접근과 발행 절차는 별도 비공개 환경에서 운영해야 한다.
- 후속 작업: 공개 블로그의 기존 CMS 콘텐츠·문서·운영 절차를 정리하고, 외부에 남아 있는 CMS 비밀값과
  Access 설정은 소유자가 폐기한다.
