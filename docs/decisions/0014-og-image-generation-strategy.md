# 0014. OG 이미지 생성 전략 — 빌드타임 Satori · 폰트 임베드 · 캐시 · 폴백

## 맥락 (Context)

NOR-27 이 메타 위생을 정리하면서 `og:image` 는 **모든 페이지가 정적 1장**(`/og-default.png`)을
가리키게 두었다. 공유 링크가 전부 같은 그림이라 글을 구분할 수 없다. NOR-28 은 이걸
**페이지별 이미지**로 바꾼다.

제약이 넷 있다.

1. **프로덕션은 완전 정적이다**(ADR 0012). 온디맨드 라우트를 하나라도 만들면 어댑터가 필요해지고,
   그 순간 이 블로그는 정적 사이트가 아니게 된다.
2. **제목이 대부분 한글이다.** 렌더러(Satori)는 시스템 폰트를 쓰지 않는다 — 폰트 데이터를 직접
   넘겨야 하고, 넘긴 폰트에 없는 글자는 **두부(□)** 로 나온다. 파일이 만들어졌다는 사실만으로는
   아무 증거가 되지 않는다.
3. **빌드가 외부에 의존하면 안 된다.** 빌드 중 폰트를 네트워크에서 받아오면 재현성이 깨지고
   오프라인 빌드가 막힌다.
4. **이미지 한 장 때문에 배포가 막히면 안 된다.** 글은 계속 늘고, 렌더는 실패할 수 있다.

## 검토한 대안 (Options)

### 생성 시점

- **A. 런타임 생성**(Cloudflare Workers / 온디맨드 라우트) — 캐시만 잘 걸면 빌드가 안 늘어난다 /
  **정적 전제를 깬다(ADR 0012)**. 탈락.
- **B. 외부 서비스**(Cloudinary·Vercel OG 등) — 빌드가 가볍다 / 외부 의존·비용·URL 수명 문제.
  개인 블로그에 과하다.
- **C. 빌드타임 생성 → 정적 파일** ✅ — 산출물이 그냥 PNG 다. 배포·CDN·크롤러 모두 단순하다 /
  빌드 시간이 는다(→ 캐시로 방어).

### 렌더러

- **D. Playwright / headless Chrome 스크린샷** — CSS 를 그대로 쓸 수 있다 / 빌드에 브라우저를
  얹어야 한다. 느리고 CI 가 무거워진다. 탈락.
- **E. Satori(HTML/CSS → SVG) + `@resvg/resvg-js`(SVG → PNG)** — 가장 흔한 조합 / 네이티브
  의존성이 하나 더 는다.
- **F. Satori + `sharp`** ✅ — `sharp` 는 이미 의존성이다(Astro 이미지 최적화). Satori 는
  `embedFont` 기본값대로 글리프를 `<path>` 로 심어 SVG 를 내보내므로, 래스터라이저에 폰트가
  없어도 한글이 그대로 나온다. 네이티브 의존성을 늘릴 이유가 없다.

### 폰트 (이 일감이 실패하는 가장 흔한 지점)

Pretendard Regular OTF(CFF) 기준 실측:

| 대상                             | 크기        | 두부 위험       |
| -------------------------------- | ----------- | --------------- |
| 원본 (전체)                      | **1537 KB** | 없음            |
| 라틴 + 자모 + 현대 한글 11,172자 | 1247 KB     | 없음 (−19%)     |
| 라틴 + 자모 + 한글 2,350자       | 324 KB      | **있음** (−79%) |
| 라틴만                           | 56 KB       | 한글 전멸       |

- **G. npm 의존성으로 폰트 받기**(`pretendard` 패키지) — 저장소는 가벼워진다 / 그 패키지는
  unpacked 97.7 MB 다(웹폰트 서브셋 수천 개 포함). node_modules 비용이 너무 크다. 탈락.
- **H. 공격적 서브셋(2,350자)을 커밋** — 648 KB(2웨이트)로 가볍다 / ① 서브셋에 없는 음절이
  제목에 들어오는 날 두부가 된다. ② OFL 의 **Reserved Font Name** 조항상 수정본에 "Pretendard"
  이름을 쓸 수 없어 리네이밍이 필요하다. ③ 서브셋 재생성이라는 수동 절차가 생긴다.
- **I. 원본 2웨이트(Regular·Bold)를 그대로 커밋** ✅ — 3.1 MB. 전체 글리프라 **두부 위험 0**,
  수정하지 않으므로 RFN 문제 없음, 절차도 없음.

## 결정 (Decision)

**빌드타임에 Satori 로 SVG 를 만들고 sharp 로 1200×630 PNG 를 떨어뜨린다. 폰트는 Pretendard
Regular/Bold OTF 원본을 저장소에 커밋해 임베드하고, 결과는 내용 주소 캐시에 저장하며, 어떤
실패도 기본 이미지로 폴백하고 빌드를 세우지 않는다.**

구체적으로:

1. **생성 위치** — `src/pages/og/[...path].png.ts` 정적 엔드포인트. `output` 미지정이라 모든
   라우트가 프리렌더 대상이고, 결과는 `dist/og/**.png` 라는 평범한 파일이다. 배포된 사이트에
   생성 코드는 남지 않는다(ADR 0012 유지). 개발 서버에서는 같은 URL 로 즉석 렌더돼 확인이 쉽다.
2. **경로 규칙** — `ogImagePath(경로)` 하나뿐이다: 사이트 트리를 그대로 `/og` 아래에 복사하고
   `.png` 를 붙인다(`/blog/x` → `/og/blog/x.png`, `/` → `/og/index.png`). 메타(`site-meta.ts`)와
   생성 목록(`og-targets.ts`)이 **같은 함수**를 쓰므로 URL 과 파일이 어긋날 수 없다.
   페이지는 이미지 경로를 넘기지 않는다 — "이 페이지만 빠뜨렸다" 가 구조적으로 불가능하다.
3. **폰트** — `src/assets/fonts/Pretendard-{Regular,Bold}.otf` (OFL 1.1, 원본 무수정, 3.1 MB).
   서브셋하지 않는다. 위 표대로 한글을 다 담으면 어차피 19% 밖에 못 줄이고, 크게 줄이려면
   글자를 버려야 해서 미래의 두부 위험과 RFN 리네이밍을 사는 셈이기 때문이다. 폰트 파일은
   한 번 커밋하면 바뀌지 않으므로 히스토리가 계속 무거워지지도 않는다.
   출처·라이선스는 `src/assets/fonts/README.md` 에 남긴다.
4. **캐시** — `src/lib/og-cache.ts` (`node_modules/.cache/og-images`). 성격은 ADR 0008 의
   `disk-cache.ts` 와 같지만 **바이너리 그대로 저장**하고(base64 +33% 를 피한다) **TTL 이 없다**
   (키가 곧 입력 해시라 시간이 지나 낡지 않는다). 키에는 카드 입력 + **테마 토큰 전체** + 규격이
   들어가므로, 색을 바꾸면 캐시가 저절로 무효화된다.
5. **폴백** — `renderOgImageOrFallback` 은 절대 던지지 않는다. 실패하면 경고를 남기고
   `public/og-default.png` 바이트를 그대로 응답한다. 그래서 **실패한 글도 `og:image` 가 가리키는
   URL 은 실재한다** — SNS 쪽에서 보면 깨진 참조가 아니라 기본 이미지다.
6. **감사** — `og-image-audit` 통합이 빌드 끝에 `dist` 의 모든 `og:image` 가 실제 파일을
   가리키는지 대조하고 **경고만** 남긴다. 규칙과 목록이 어긋나면 HTML 만 봐서는 알 수 없어서다.

## 근거 (Rationale)

- 정적 전제(ADR 0012)를 지키는 방법 중 가장 단순한 것은 "빌드타임에 파일로 떨어뜨리기"다.
  산출물이 PNG 파일이면 캐시·CDN·크롤러 어느 쪽에도 특별한 사정이 없다.
- 두부는 이 일감의 유일한 치명적 실패다. **19% 를 아끼려고 두부 위험을 사지 않는다.**
  3.1 MB 는 8.4 MB 짜리 저장소에 한 번 얹는 비용이고, 두부는 공유될 때마다 드러나는 비용이다.
- 렌더 비용 실측(같은 머신, 46장): **첫 장 1.11 s**(폰트 파싱·레이아웃 엔진 초기화 포함),
  **46장 전부 11.62 s**, **캐시 히트 46장 0.03 s**. 지금 규모는 캐시가 없어도 견딜 만하지만
  글이 늘수록 선형으로 는다. 캐시는 그 선형 증가를 **바뀐 카드만**으로 줄인다.
- 실패를 예외로 올리면 "OG 이미지 하나 때문에 블로그 배포가 막히는" 일이 생긴다. 폴백 + 경고가
  ADR 0008(커스텀 블럭)에서 이미 쓰고 있는 이 저장소의 실패 처리 방식이다.

## 영향 (Consequences)

- 긍정
  - 글마다 제목·시리즈가 보이는 카드가 생겨 공유 링크가 구분된다.
  - `og:image:width/height/type/alt` 까지 함께 나가 SNS 가 레이아웃을 미리 잡고, 스크린리더도 읽는다.
  - 색·타이포가 `OG_THEME` 한 곳에 모여 있어 NOR-24(베이스 테마)에서 값만 갈아끼우면 된다.
  - 텍스트 배치의 순수 계산(`og-text.ts`)이 단위 테스트로 고정된다.
- 부정/비용
  - 저장소에 폰트 3.1 MB 가 들어간다(1회, 이후 변경 없음).
  - 캐시가 빈 상태의 빌드는 46 장 렌더만큼 느려진다(실측치는 spec NOR-28 참고).
  - **템플릿 구조**를 바꾸면 `og-render.ts` 의 `RENDERER_VERSION` 을 올려야 한다(토큰 값 변경은
    자동 무효화되지만 구조는 키에 안 들어간다).
- 후속 작업
  - NOR-21 이 `/about` 을 만들면 `buildOgTargets` 에 한 줄 추가로 About 카드가 붙는다(템플릿은 이미 있다).
  - NOR-24 에서 테마가 확정되면 `OG_THEME` 값을 사이트 토큰으로 교체한다.
